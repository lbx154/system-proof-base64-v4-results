## Source argument for v2

The sole candidate edit is remove_ignored_trait_bounds_from_predicates in rust_to_vir_func.rs:2801-2820. Its new branch requires in_trait, a present exact ex_trait_assoc type argument, a projection alias whose associated item's parent occurs in trait_ids, exact equality of the bound's Self argument to that alias, and the compiler-resolved MetaSized lang-item DefId. It therefore cannot match a generic parameter, another associated type, a lookalike trait name, or a different bound on the marker. The remaining predicate filtering is unchanged.

external_trait_specification_of in rust_to_vir_trait.rs:69-113 obtains that alias from the named marker's one substantive positive trait bound. It ignores Sized only; explicit additional MetaSized or Clone is rejected as a second bound, before this filter. The marker itself is skipped at trait translation (:278); it is identification scaffolding, not a runtime associated-type operation. Rust typechecking runs before these checks.

Trait comparison (:174-224) instantiates external and proxy predicates using the external trait reference arguments. The alias's defining parent is the proxy trait. The external list passes only [external_trait_id], so v2's added branch cannot remove a real external Self: MetaSized, even though instantiation has renamed external Self to the marker alias. The proxy list passes [external_trait_id, proxy_trait_id], allowing the compiler-generated marker bound to be dropped. Generic bounds do not have that alias as Self. Unmatched predicates still reach predicates_match, which compares list length and removes each exact anonymized-binder match once; this is a multiset comparison, not subset acceptance. This source argument explains preservation of actual external trait-level Self and generic constraints for this pinned route.

V1 omitted the defining-parent guard. It could drop a real external Self: MetaSized on both sides after instantiation. Its rejection is mandatory; never integrate the v1 patch or infer admissibility from its positive outputs. Retained v1 patch and original/v2 diagnostics are preserved unchanged in source/.

All other callers of the changed filter in handle_external_fn (:1091,1099) supply ex_trait_assoc=None, so the new branch is inert there. There is an important independent existing limitation at :1108-1112: external_trait_from_to.is_some() bypasses method predicate equality. Thus the broad statement that all method-level constraints are automatically checked is unsupported. For this exact interface, source inspection must remain part of the TCB acceptance: the real AsRef and proxy method both have only &self -> &T with the same elided receiver-bound lifetime and no extra method where clauses. Any method/generic/lifetime/safety change needs renewed comparison; do not extrapolate this assessment to arbitrary trait extensions. A non-weakening broader alternative is to implement and test the missing renamed method-predicate comparison, or separately check exact method correspondence for each admitted external boundary.

Linkage is to the real method: translate_trait looks up the actual associated item by identifier and kind in the selected external trait, passes its DefId to check_item_fn/handle_external_fn, and translates the contract onto the external path. handle_external_fn equalizes early/late substitutions and compares function input/output types; this includes reference lifetimes. However, compare_external_sig in source/rust_to_vir_func.rs:882-883 explicitly ignores ABI and safety (for rust-intrinsics). Signature comparison therefore does not validate agreement in either ABI or safety; these are an additional existing TCB correspondence condition, separate from the method predicate bypass. Extension macro expansion in syntax_trait.rs:212-251 requires the marker's single syntax bound; translate_impl in rust_to_vir_impl.rs:133 maps the extension impl trait to its spec trait with concrete type arguments and translated bounds. This is trusted specification attachment, not verification of the core method body. The frontend, macro, trait dispatch and solver remain explicit TCB components. No global soundness proof of them is supplied.

Safety/ABI correspondence was separately checked against the exact retained declarations: core convert source :221-224 declares `fn as_ref(&self) -> &T`; replay/borrowed-slice-pointee-self.rs:10 declares the proxy `fn as_ref(&self) -> (ret: &T)`. Neither declaration has `unsafe` or `extern`, so both are safe methods with the default Rust ABI. The named Verus return binder does not change the executable signature. The corresponding real reference implementation (:719) and slice implementation (:849) likewise declare ordinary safe `fn as_ref` methods with no `extern` qualifier, hence the same Rust ABI. The spec-only forwarding impls introduce no replacement executable method. This establishes agreement for these exact admitted declarations by source inspection, not by compare_external_sig. The real const-trait decoration does not supply an alternative safety or ABI guarantee; this assessment concerns ordinary runtime calls. Any unsafe/extern or method-signature revision must be separately checked before admission.

## Standard conversion correspondence

Pinned rustc is 1.98.1, commit 48a229ceaefd4985c50990b14116b6d856af0985. Retained core convert source :847-852 implements AsRef<[T]> for [T] by returning self. Therefore the slice view postcondition ret@ == self@ is valid, and the actual returned reference has the same slice data address, length and receiver-derived lifetime. The proposed contract proves byte/element sequence equality only; it does not formally encode pointer identity, ownership, provenance or a stronger lifetime. Consumers needing those observations must add an explicit, source-supported interface and review it.

Core convert :714-722 implements AsRef<U> for &T where T: AsRef<U>, by one call to <T as AsRef<U>>::as_ref(*self). The proposed reference post delegates exactly to the underlying T post. It has no blanket identity promise for arbitrary T. PointeeSized on Self/T/U matches the real broad trait/reference sizing hierarchy; generic [T] impl matches the real generic slice impl. The earlier monomorphic impl and bound-chain failure logs in t3 remain diagnostic exclusions, not alternatives to integrate.

Returning self and forwarding the shared reference are supported by the real bodies and ordinary Rust reference/lifetime semantics. These bodies are externally specified, not machine-checked here, so pinning the standard library and accepting that correspondence are required TCB conditions. For [u8], shared borrowing supports unchanged bytes during the subsequent codec call; it does not imply arbitrary reachable object state preservation. The forwarding contract imposes no universal repeated-call stability, no global purity, no termination/no-panic property, and no destructor guarantee for arbitrary user T. Unsupported pointer identity reasoning must not be inferred solely from sequence equality.

The original-revision t2 Panics AsRef and t4 stateful sizing mismatch remain authoritative counterexamples: legal user code may panic; separate conversion evaluations may return different lengths and invalidate earlier sizing. Owned T may also run Drop after conversion/codec. These interfaces cannot prove unconditional generic whole-call no-panic, a stable ghost View of arbitrary T, pre-conversion destination framing, or destruction purity. Snapshot destination state after the actual conversion; preserve exact reported bytes and success on the original lawful codec domain. Keep custom conversion and Drop boundaries explicit, rather than narrowing public APIs or weakening success to an implication on Ok.
