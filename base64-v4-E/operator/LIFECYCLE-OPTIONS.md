## Source-bound ownership trace

Production src/engine/mod.rs:227-255 defines encode_slice<T: AsRef<[u8]>>(input: T, output_buf: &mut [u8]); :386-409 defines decode_slice with the same by-value ownership. These are Engine trait default methods used by GeneralPurpose, not separate GeneralPurpose overrides. Candidate equivalents are src/engine/mod.rs:265 and :465, with as_ref_bytes at :628-630. t21 accepted the exact one-call extraction and runtime order correspondence.

1. The caller transfers input T into the public call. &self and the destination are borrowed. If T is a reference, only the reference value transfers; the referent remains caller-owned. Entry does not establish an arbitrary T byte View or global frame.
2. Each production wrapper evaluates input.as_ref() exactly once, borrowing its owned input. Arbitrary AsRef code runs here. If it returns, the resulting &[u8] defines this invocation's effective input. Its shared lifetime and valid byte-slice representation are legitimate boundaries; they do not force callback completion, purity, or equality to an earlier conversion. Candidate as_ref_bytes(&input) snapshots these returned bytes and the destination before codec work, not a universal pre-conversion object state.
3. Encoding inner computes encoded_len(effective.len(), config padding), checks capacity, restricts the destination to that exact length, calls encode_with_padding, and produces Ok(encoded_size). The accepted adapted body expands padding while preserving order. Under STANDARD, supported effective length and sufficient actual capacity, checked scalar bodies establish exact standard_encoding bytes/count and unchanged destination suffix; no supported codec Err or assertion panic is allowed.
4. Decoding inner obtains internal_decoded_len_estimate from the SAME effective input length, calls internal_decode and maps metadata to its decoded_len. Accepted bodies derive compatible remainder/estimate metadata from that constructor. For an effective slice equal to the exact successful encoding prefix, with sufficient destination capacity, the result is Ok(original length), exact original bytes and unchanged suffix. Capacity-only metadata from some other length is not the public path.
5. The effective slice borrow expires, then the public call's owned input is destroyed as part of scope exit before result delivery. Destruction includes user Drop and owned field cleanup, not just an explicit destructor method. Normal destruction allows the prepared Result to reach the caller. Panic initiates unwind (or process termination under panic-abort); nonreturning destruction prevents delivery indefinitely. A conversion panic can also initiate owned cleanup before any codec writes, and cleanup may itself fail. These are caller-code effects outside the byte-level checked closure; no universal unwind/abort cleanup theorem is claimed.
6. Only after normal public completion can the caller use the reported count to borrow encoded_output[..written] and start decoding. If encoding destruction fails, the correct prefix may already exist but the promised result is unavailable. If decoding destruction fails, recovered bytes may already exist but its count is unavailable. Calling context can perform its own effects after receipt; no claim about arbitrary caller continuation follows.

Public encoded_len (production src/encode.rs:101) takes a usize and bool by value; public decoded_len_estimate (production src/decode.rs:189) takes usize. Neither owns arbitrary T or calls AsRef/Drop. Their checked arithmetic supports sizing; they cannot predict a later stateful conversion. helper_sized_round_trip (candidate src/round_trip_use.rs:29) takes &[u8], obtains STANDARD, calls both real helpers, derives capacities, uses encode's exact reported prefix and consumes decode's guarantee. Its input and prefix reference values have no arbitrary owned destructor. This is a checked source-grounded borrowed caller, not universal verification of owned custom inputs or their surrounding applications. Passing &Custom avoids destroying Custom in this API call but still forwards to Custom's AsRef and does not establish total conversion.

## Preserved domain, frames and witnesses

For the actual returned byte sequence x of length n, E(n)=4*ceil(n/3), D(e)=3*ceil(e/4). Valid represented byte slices have maximum extent M=isize::MAX. The capacity-derived domain is n <= 3*floor(M/4), with encode output >= E(n) and helper-sized decode output >= D(E(n)); n <= D(E(n)) <= n+2. On 64-bit n_max=6917529027641081853 and E_max=9223372036854775804. No allocated huge-buffer example is asserted. Input immutability and suffix frames concern sound borrowed byte slices and the two supplied destinations, not every field owned by T or the whole external heap. Safe callbacks/destructors can change Rc<RefCell<_>> event state. Explicit global effects would need separate stated observations and verified callback/frame contracts, if authorized.

Retain all t22 witnesses and their receipts, not just the favorable borrowed case:

- drop/drop-probe.rs and drop.log: owned safe input b"f", encoded_len(1,true)=4, output length8; correct b"Zg==" and four unchanged 0xa5 suffix bytes. Decoding exactly b"Zg==", D(4)=3, output length8; correct b"f" and seven unchanged suffix bytes. Each converts once normally. Panic-Drop cases have [convert,drop], unwind=true, no caller-consumes; normal controls have [convert,drop,caller-consumes] and correct count. These are sufficient-effective-capacity whole-call counterexamples for BOTH APIs.
- conversion-probe.rs/conversion.log: safe custom AsRef panic before codec; 12,309 successful bounded original cases do not prove arbitrary callbacks total.
- frame.log: stateful AsRef sizing x then encoding a longer slice, requiring8 with capacity4. It refutes assumed inter-call stability but is not a sufficient-effective-capacity codec counterexample.
- estimate.log: internal length1/2/3 estimates have capacity3 but wrong remainder for Zg==; actual length4 constructor succeeds. This is not a public-path failure or a new legitimate public readiness premise.

The retained official RFC4648 section10 comparison in t13/published-rfc4648.txt agrees with f -> Zg== (four encoded bytes, one recovered byte). This is reuse of published retained evidence, not fresh online retrieval. Exact core AsRef interfaces are the pinned t7 source comparison, not a moving documentation promise that custom Rust code cannot panic.

No-panic alone does not mean termination: an AsRef or destructor can loop without panicking. A normally returning conversion does not mean purity or stability. Nonpanicking terminating destruction can mutate external state. A finite timeout diagnoses lack of observed completion, not mathematical nontermination; the nontermination possibility here follows from unrestricted executable user code and is not presented as a new test result.

## Precise observation boundary for any authorized conditional claim

The codec snapshot is the actual effective immutable slice and destination state AFTER the single conversion returns, BEFORE codec writes. The checked codec suffix is relative to that snapshot. Normal terminating nonpanicking caller code alone supplies no preservation of observed buffers across conversion or cleanup. A conditional WHOLE-CALL claim about entry-to-return input/destination contents must additionally enumerate and justify that conversion and complete owned cleanup preserve every observed input byte and destination region required by the claim (including both destination suffixes), maintain valid effective capacities, and do not alter the exact reported-prefix identity before decoding. Use sound exclusive borrows where they establish these facts; otherwise verify concrete effect contracts or make explicit operator-authorized conditions. These are distinct from global purity, which is neither supplied nor required implicitly. If only post-conversion codec observations are claimed, say so explicitly: they do not alone discharge entry-to-return frames. Option B would require separately named completion AND observed-buffer-effect obligations and a revised usage claim, with original canonical contracts preserved. No such conditions are added here.
